# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Diff stays inside the plan | Every hunk of the diff (each changed file and each change within it), read against the plan's stated scope, its files list, its not-in-scope lines, and its deviation notes | Every change in the diff is the planned fix, its tests, or something a deviation note in the plan explicitly covers. Fails if any hunk adds work the plan does not cover: a new option, flag, or setting; a rename or refactor pass; a rewrite of code outside the fix; a change to a file the plan never names; or anything the plan's not-in-scope line excludes. Fails even when the extra work is good or adjacent, and fails regardless of what the description says about it | required |
| Plan delivered as the description claims | The plan's promised changes and the description's claims about what the PR does, each read against the diff | Everything the plan promises is in the diff, OR the shortfall is disclosed as a deferral in the plan's deviation notes or in the description. And every claim the description makes about the change is true of the diff: claims like "implements the plan exactly", "no changes beyond X", or "now documents Y" are checked against the hunks themselves. Fails if a planned piece is missing with no disclosure, or if the description claims something the diff does not contain or denies something it does | required |
| Test evidence shows the fix on the plan's repro | The test-evidence section (and any before/after in the description), read against the plan's test plan and the repro it names | The evidence re-runs the repro the plan's test plan names, through the code path the fix changes, and shows an observable before and after: the failing output or behavior before, and the expected-after the plan states. When the plan's test plan names more than one repro of the bug (more than one failure mode), each one gets its own before/after. Secondary checks the plan names (a smoke check, a control expected unchanged, a suite or check run) need only their outcome stated, not a before/after. Fails on "tests pass" or "verified locally" with no observable shown, on evidence that only exercises an unchanged path or a control, or when a repro the plan named is never re-run | required |
| Diff is free of debris | The diff's hunks and the commit list | The diff contains only the change and its tests. Fails if any hunk carries debug output left in (prints, `eprintln!`, `console.log`), commented-out code or earlier attempts, dead functions or `allow(dead_code)`/unused helpers, TODO/FIXME left on unrelated lines, or churn unrelated to the fix (re-indenting, re-ordering imports, re-wrapping unchanged lines). Explanatory comments on the fix itself are not debris | required |
| Repo's PR template and asks are honored | The repo-facts PR template and contributing asks (live mode: `.github/PULL_REQUEST_TEMPLATE.md` and `docs/CONTRIBUTING.md`), read against the description and the diff | Every section and item the template or contributing guide requires for a PR is honored with real content: required sections are filled (headed any way, as long as the content is there), a required issue-link line ("Closes #N", "fixes #N") is present with the real number, required checklist items are answered truthfully, and any artifact the template requires in the diff (a changelog or whatsnew entry, regenerated docs) is actually in the diff. Fails if a required section, line, checklist, or artifact is visibly missing. Passes when the repo states no template and the change meets the contributing guide's stated asks | required |
| AI use disclosed where required | The repo-facts contribution policy (live mode: `docs/CONTRIBUTING.md` and any AI-policy file), and the description for a disclosure statement | In eval mode, fails only when the stated policy requires disclosing AI usage (on PRs or "in any form") and the description has no disclosure. Passes when the policy is silent, asks only for human-written text, or the disclosure is present. In live mode, the course always requires a disclosure: the description must say in the student's own words how AI was used on the change, whatever the repo's policy says | required |

## Verdict rule

Accept (ready to submit) only if all six required checks pass. Reject
(hold) if any required check fails. An `unclear` grade counts as a
fail: a PR whose package cannot show a claim is not ready to submit.
There are no preferred checks. An honestly disclosed shortfall is not a
fail by itself: a deferral recorded in the plan and restated in the
description passes "Plan delivered as the description claims", and the
PR is graded on the change it says it makes.
